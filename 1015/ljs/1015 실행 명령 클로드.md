## A. P3 — 커널 잠금 증거 수집 (가장 중요)

> **주의:** `wsl --shutdown`이나 재부팅을 하기 **전에** 실행해야 합니다.
> 밤사이 재부팅됐다면 `blocked_full.txt`는 이미 저장돼 있으니 A-1, A-2는 그대로 하고 A-3(dmesg)만 건너뜁니다.
> WSL 안에서 `ip`, `ifconfig`, `sudo`는 실행하지 마세요. 실행할 때마다 멈춘 프로세스가 하나씩 쌓입니다.

**A-1. 잠금을 쥔 커널 스레드 후보 추출**
```powershell
Select-String -Path C:\Users\admin\blocked_full.txt -Pattern 'kworker|netvsc|vmbus|rndis|unregister_netdevice|netdev_run_todo|wait_for_completion|synchronize' -Context 3,25 | Out-File C:\Users\admin\blocked_holders.txt
```

**A-2. 전체 파일 압축 (첨부용)**
```powershell
Compress-Archive C:\Users\admin\blocked_full.txt C:\Users\admin\blocked_full.zip -Force
```

**A-3. 멈춘 작업 종류별 집계 (kj-command-6)**
```powershell
Select-String -Path C:\Users\admin\blocked_full.txt -Pattern 'task:' | % { ($_.Line -split 'task:')[1] -replace ' stack:.*','' } | Group-Object | Sort-Object Count -Descending | Format-Table Count,Name -AutoSize
```

**A-4. 커널 로그 (재부팅됐다면 건너뜀)**
```powershell
wsl -d Ubuntu-22.04 -u root -e sh -c "dmesg | grep -iE 'unregister_netdevice|netvsc|vmbus|eth2' | tail -100"
```

**올릴 것:** `blocked_holders.txt`, `blocked_full.zip`, A-3·A-4 결과

**A 완료 후 복구:**
```powershell
wsl --shutdown
wsl --update
wsl --version
```
(`--terminate`는 멈출 수 있으니 쓰지 않습니다. 업데이트 후 P2 수준인 2.7.13 이상인지 확인합니다.)

## B. P2 · P3 · P4 — Wi-Fi 리셋 비교 (세 대 모두 실행)

```powershell
Get-WinEvent -FilterHashtable @{LogName='System'; StartTime=[datetime]'2026-10-13 00:00'} | ? { ($_.ProviderName -eq 'Netwtw14' -and $_.Id -in 7021,7003,8000) -or $_.Id -eq 4003 } | sort TimeCreated | select TimeCreated,ProviderName,Id | ft -AutoSize
```

**올릴 것:** 호기별 결과 (파일명에 P2 / P3 / P4 표시)

**해석:**
- P2·P4에도 4003이 있는데 WSL이 멀쩡함 → P3의 WSL 버전(2.7.8)이 원인. 업데이트로 해결.
- P2·P4에는 4003이 거의 없음 → P3 위치의 AP/로밍 문제. E가 중요.

## C. P3 — 게이트웨이 ping 로거 (여유 있으면, 아침에 켜 두기)

```powershell
New-Item -ItemType Directory -Force C:\Temp | Out-Null
ping.exe -t 10.249.138.1 | % { "{0:HH:mm:ss.fff} {1}" -f (Get-Date), $_ } | Out-File C:\Temp\gw-ping.log
```
창은 켜 둔 채로 두고, 다음 4003 발생 후 `C:\Temp\gw-ping.log`를 올립니다.

- 대상 MAC: `40:d1:33:cd:46:69` (P3)

- 요청 내용:
  1. 각 시각의 로밍 방식 (OKC / PMK 캐시 / 802.11r)
  2. 로밍 직후 약 15초 동안 트래픽이 실제로 전달됐는지
  3. 로밍 전/후 BSSID
