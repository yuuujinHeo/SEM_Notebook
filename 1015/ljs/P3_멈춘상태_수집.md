# P3(.60) 멈춘 상태 증거 수집 — 재시작 전에만 가능

**재시작, `wsl --shutdown`, `wsl --terminate` 금지.**
WSL 안에서 `ip`, `ifconfig`, `hostname`, `sudo`, `nmcli`, `/sys/class/net/...` 사용 금지 (실행할 때마다 멈춘 프로세스가 하나씩 쌓임).
모든 명령은 **Windows PowerShell(관리자)** 에서 실행합니다.

## 1. 리눅스 커널 상태 (재시작하면 사라짐)

1) `frozen.sh`를 `C:\Temp\frozen.sh`로 저장합니다.
2) 실행합니다:
```powershell
New-Item -ItemType Directory -Force C:\Temp | Out-Null
wsl -d Ubuntu-22.04 -u root -e sh -c "tr -d '\r' < /mnt/c/Temp/frozen.sh | sh"
```
화면에 [0]~[7]이 차례로 찍히고 "완료"가 나오면 됩니다.
특정 번호에서 1분 넘게 멈추면 Ctrl+C를 누르고, 몇 번에서 멈췄는지 알려 주세요.

3) 결과가 잘리지 않았는지 확인합니다. 아래 명령의 첫 줄이 "sysrq: Show State"로 시작하면 정상입니다.
```powershell
Get-Content C:\Temp\frozen\05_sysrq_t.txt -TotalCount 3
```

## 2. Windows 쪽 현재 상태 (WSL을 끄면 함께 초기화되는 것)

```powershell
$o='C:\Temp\frozen'
hnsdiag list all                          > $o\win_hns.txt 2>&1
Get-NetAdapter -IncludeHidden | fl *      > $o\win_adapters.txt
Get-NetIPAddress | ft -AutoSize           > $o\win_ip.txt
Get-NetRoute | ft -AutoSize               > $o\win_route.txt
Get-NetIPInterface | ft -AutoSize         > $o\win_ipif.txt
Get-NetFirewallHyperVVMSetting -ErrorAction SilentlyContinue | fl * > $o\win_hv_fw.txt
```

## 3. Windows 이벤트 (재시작해도 남지만, 같이 뽑아 두면 편함)

10/14 08:30~08:45 사이 Hyper-V와 HNS 쪽 기록입니다.
```powershell
$s=[datetime]'2026-10-14 08:30'; $e=[datetime]'2026-10-14 08:45'
foreach($l in 'Microsoft-Windows-Hyper-V-Compute-Operational','Microsoft-Windows-Host-Network-Service-Admin','Microsoft-Windows-Host-Network-Service-Operational','System'){
  Get-WinEvent -FilterHashtable @{LogName=$l;StartTime=$s;EndTime=$e} -ErrorAction SilentlyContinue |
  select @{n='T';e={$_.TimeCreated.ToString('HH:mm:ss.fff')}},LogName,ProviderName,Id,Message
} | Export-Csv C:\Temp\frozen\win_events_0838.csv -NoTypeInformation -Encoding UTF8
```

## 4. 압축해서 올리기

```powershell
Compress-Archive C:\Temp\frozen\* C:\Temp\P3_frozen.zip -Force
```
`P3_frozen.zip`을 `1015/ljs/`에 올립니다. 이 단계가 끝날 때까지 **재시작하지 않습니다.**

### 이 자료로 확인하려는 것
- **RTNL을 쥔 주체:** 03, 05에서 `rtnl_lock`을 기다리는 게 아니라, 잠금을 쥔 채 다른 것을 기다리는 스택을 찾습니다(hv_netvsc, rndis_filter, vmbus, wait_for_completion, flush_work, synchronize_rcu 등). 이게 원인 코드 위치입니다.
- **작업 큐 정체:** 05 끝부분의 "Showing busy workqueues"에서 멈춘 kworker를 확인합니다.
- **WSL 미러링 프로세스(GNS) 상태:** 08:38 이후 NIC Add/Remove를 더 반영하지 못한 이유를 봅니다.
- **Windows 쪽에서 본 eth2 상태:** HNS 엔드포인트가 리눅스 쪽과 어긋나 있는지 확인합니다.
