# Windows Wi-Fi 연결 불안정 원인 분석 보고서

- 작성일: 2026-10-15
- 대상: 물류1, 물류2, 공정2, 공정3, 공정4
- 분석 장비: 총 5대
- 무선랜: Intel Wi-Fi 6E AX210 / AX211
- 무선 환경: 5GHz, WPA2-Enterprise, 802.11ax
- 분석 목적: 정상 장비와 장애 장비의 Wi-Fi 설정 차이를 비교하여 연결 불안정 원인을 파악한다.

---

## 1. 분석 결론 요약

총 5대의 Windows Wi-Fi 설정을 비교한 결과, 정상 장비와 장애 장비 사이에서 다음과 같은 공통적인 차이가 확인되었다.

### 정상 장비 (물류1, 물류2)

- Intel AX210 사용
- 무선랜 드라이버: `22.0.1.5`
- Wi-Fi 채널: 36, 48
- 비DFS 채널 사용
- WPA2-Enterprise 인증
- Wi-Fi 연결이 상대적으로 안정적

### 장애 장비 (공정2, 공정3, 공정4)

- Intel AX210 또는 AX211 사용
- 무선랜 드라이버: `23.110.0.5`, `24.70.0.3`
- Wi-Fi 채널: 60, 116
- DFS 채널 사용
- WPA2-Enterprise 인증
- Wi-Fi 연결 불안정 현상 발생

### 현재 판단

**정상 장비는 구버전 드라이버와 비DFS 채널을 사용하고, 장애 장비는 상대적으로 최신 드라이버와 DFS 채널을 사용한다는 공통 패턴이 확인되었다.**

따라서 다음 두 가지를 우선 조사할 필요가 있다.

1. Intel 무선랜 드라이버와 AP/802.1X 인증 환경의 호환성
2. DFS 채널 사용에 따른 AP 채널 변경 및 연결 중단 여부

단, 드라이버 버전과 AP 채널이 동시에 다르므로 현재 자료만으로 어느 쪽이 실제 원인인지 확정할 수 없다.

## 3. 장비별 상세 분석

### 3.1 물류1 — 정상

```text
무선랜       : Intel AX210
드라이버     : 22.0.1.5
SSID         : sWave_works_shared
BSSID        : b8:3a:5a:cd:1d:71
채널         : 36
DFS          : 미사용
RSSI         : -72 dBm
신호         : 62%
수신 속도    : 172 Mbps
송신 속도    : 287 Mbps
검색 BSSID   : 23개 (동일 SSID)
상태         : 정상
```

#### 특징

- 비교 대상 중 신호가 상대적으로 약한 편이다.
- 동일 SSID의 AP가 23개 검색된다.
- 그럼에도 Wi-Fi 연결이 상대적으로 안정적이다.
- 비DFS 채널 36을 사용한다.

#### 판단

주변 AP가 많이 검색된다는 사실 자체가 Wi-Fi 연결 불안정의 직접적인 원인이라는 가설은 약해진다.

또한 RSSI가 -72 dBm임에도 정상적으로 운영되므로, 단순 신호 세기만으로 장애를 설명하기 어렵다.

```text
RSSI         : -67 dBm
신호         : 75%
수신 속도    : 229 Mbps
송신 속도    : 287 Mbps
검색 BSSID   : 1개 (동일 SSID)
상태         : 심각한 장애
```

#### 특징

- 정상 물류 장비와 동일한 AX210을 사용한다.
- 드라이버 버전은 `24.70.0.3`으로 다르다.
- DFS 채널 116을 사용한다.
- Wi-Fi 연결 관련 이벤트가 반복 발생한다.
- Windows Wi-Fi 이벤트 직후 WSL 네트워크 정체가 관찰되었다.
- WSL에서 RTNL 관련 작업이 D 상태로 대기하였다.

#### 추가 관찰

`netsh wlan show interfaces`에서는 다음 AP에 연결되어 있었다.

```text
BSSID : b8:3a:5a:cc:b7:31
채널  : 116
RSSI  : -67 dBm
```

그러나 이어서 실행한 `netsh wlan show networks mode=bssid`에는 다음 AP만 표시되었다.

```text
BSSID : b8:3a:5a:d1:56:91
채널  : 132
신호  : 82%
```

현재 연결된 BSSID가 스캔 결과에 나타나지 않는 현상이 확인되었다.

이는 스캔 시점 차이, 부분적인 스캔 결과, 채널 탐색 방식 등으로 발생할 수 있다.

따라서 이 결과만으로 AP 로밍 또는 Wi-Fi 드라이버 오류를 확정할 수는 없다.

#### 판단

공정3은 Windows Wi-Fi 연결 변화와 WSL 네트워크 정체 사이의 연관성을 추가로 조사해야 하는 핵심 대상이다.

## 4. 원인 후보 분석

### 4.1 원인 후보 1 — Intel 무선랜 드라이버 호환성

#### 비교 결과

정상 장비:

```text
물류1 : AX210 / 22.0.1.5 / 정상
물류2 : AX210 / 22.0.1.5 / 정상
```

장애 장비:

```text
공정2 : AX211 / 23.110.0.5 / 불안정
공정3 : AX210 / 24.70.0.3 / 심각
공정4 : AX210 / 24.70.0.3 / 불안정
```

#### 가능한 문제

드라이버 버전에 따라 다음 동작이 달라질 수 있다.

- AP 로밍 처리
- WPA2-Enterprise 인증 처리
- 802.1X 재인증
- 암호화 키 갱신
- 802.11ax 기능 처리
- 무선랜 절전 동작
- 연결 해제 이후 자동 복구

#### 판단

드라이버 버전과 장애 발생 여부 사이에 뚜렷한 상관관계가 확인되었다.

특히 동일한 AX210을 사용하는 정상 물류1·2와 장애 공정3·4의 드라이버 버전 차이는 검증할 가치가 높다.

그러나 공정과 물류의 AP 및 무선 환경도 다르기 때문에 드라이버 자체 결함으로 확정할 수는 없다.

---

### 4.2 원인 후보 2 — DFS 채널 사용

#### DFS란?

DFS(Dynamic Frequency Selection)는 5GHz 무선랜에서 레이더와의 간섭을 방지하기 위해 사용하는 기능이다.

AP가 레이더 신호를 감지하면 해당 채널 사용을 중단하고 다른 채널로 이동해야 할 수 있다.

이 과정에서 연결 중단이나 재연결이 발생할 수 있다.

#### 장비별 채널

```text
[정상]

물류1 : 채널 36  / 비DFS
물류2 : 채널 48  / 비DFS

[장애]

공정2 : 채널 60  / DFS
공정3 : 채널 116 / DFS
공정4 : 채널 60  / DFS
```

#### 판단

정상 장비는 모두 비DFS 채널에 연결되어 있고, 장애 장비는 모두 DFS 채널에 연결되어 있다.

따라서 AP의 DFS 레이더 감지 및 채널 변경 이력을 확인할 필요가 있다.

단, DFS 채널 사용 자체가 장애를 의미하지는 않는다.

실제 DFS 이벤트가 장애 시각에 발생했는지 확인해야 한다.

---

### 4.3 원인 후보 3 — WPA2-Enterprise 인증 문제

모든 장비가 WPA2-Enterprise 인증을 사용한다.

이 인증 방식에서는 AP 및 인증 서버와의 통신 과정에서 다음 문제가 발생할 수 있다.

- 802.1X 재인증 실패
- RADIUS 인증 지연
- 암호화 키 갱신 실패
- 로밍 중 인증 컨텍스트 전달 실패
- AP 컨트롤러와 드라이버 간 호환성 문제

공정3의 기존 로그에서는 Wi-Fi 연결 관련 이벤트와 보안 관련 이벤트가 관찰되었다.

따라서 장애 발생 시각을 기준으로 Windows WLAN 이벤트와 AP/RADIUS 인증 로그를 비교해야 한다.

---

### 4.4 원인 후보 4 — 무선 환경 및 AP 설정 차이

정상 장비는 물류 구역, 장애 장비는 공정 구역에 위치한다.

공정 구역은 다음과 같은 영향을 받을 수 있다.

- 금속 설비에 의한 전파 반사
- 다중 경로 간섭
- 채널 혼잡
- AP 출력 및 채널 설정
- AP 로밍 정책
- 특정 AP의 장애
- AP 컨트롤러 설정 차이

따라서 드라이버 차이만으로 장애를 설명하기보다는 공정 구역의 무선 환경을 함께 분석해야 한다.

### 분석

다만 RSSI는 특정 시점의 값이므로 다음 항목은 별도로 확인해야 한다.

- 순간적인 RSSI 하락
- SNR
- 패킷 재전송률

- 무선 간섭

## 7. 공정3 WSL 네트워크 장애와의 연관성

공정3에서는 Windows Wi-Fi 연결 관련 이벤트 이후 WSL 네트워크 명령이 정체되는 현상이 관찰되었다.

기존 커널 진단 자료에서 다음 스택이 확인되었다.

```text
Workqueue: hv_vmbus_rescind vmbus_onmessage_work

schedule
rndis_filter_device_remove
netvsc_remove
vmbus_remove
vmbus_onoffer_rescind
```

동시에 다수의 프로세스가 RTNL 락을 기다리는 상태였다.

## 10. 최종 결론

총 5대의 Wi-Fi 설정 비교 결과 다음 사항이 확인되었다.

### 확인된 사실

1. 정상 물류1·2는 AX210 드라이버 `22.0.1.5`를 사용한다.
2. 장애 공정3·4는 AX210 드라이버 `24.70.0.3`을 사용한다.
3. 장애 공정2는 AX211 드라이버 `23.110.0.5`를 사용한다.
4. 정상 물류1·2는 비DFS 채널 36·48에 연결되어 있다.
5. 장애 공정2·3·4는 DFS 채널 60·116에 연결되어 있다.
6. 장애 장비의 RSSI가 정상 장비보다 반드시 낮지는 않다.
7. 검색된 AP 개수와 장애 발생 여부 사이에 일관된 관계가 확인되지 않았다.

### 유력한 원인 후보

**1순위 조사 대상**
- Intel 무선랜 드라이버와 AP/802.1X 환경의 호환성
- DFS 채널에서의 AP 동작 및 채널 변경 이벤트

**추가 조사 대상**
- WPA2-Enterprise 재인증
- AP 로밍
- 공정 구역 RF 환경
- 무선랜 고급 설정 및 전원 관리

### 현재 결론

정상 장비와 장애 장비 사이에서 무선랜 드라이버 버전과 DFS 채널 사용 여부가 뚜렷하게 구분된다.

그러나 두 조건이 동시에 다르므로 현재 단계에서는 드라이버 또는 DFS 채널 중 어느 것이 실제 장애 원인인지 확정할 수 없다.

따라서 **WLAN/AP 로그 분석을 통해 실제 연결 해제 원인을 확인한 후, 드라이버와 AP 채널을 각각 독립적으로 변경하는 비교 시험을 진행하는 것이 가장 합리적이다.**

공정3의 WSL 네트워크 정체는 Windows Wi-Fi 연결 변화와 연관된 별도 문제일 수 있으므로, Wi-Fi 연결 안정화와 WSL 네트워크 복구 방안도 병행 검토해야 한다.

## 11. 보고용 간단 요약

물류1·2 및 공정2·3·4 총 5대의 Windows Wi-Fi 환경을 비교한 결과, 정상 물류 장비는 Intel AX210 드라이버 22.0.1.5와 비DFS 채널(36, 48)을 사용하고, 장애가 빈번한 공정 장비는 상대적으로 최신 드라이버와 DFS 채널(60, 116)을 사용하고 있는 것으로 확인되었다.

특히 공정3·4는 정상 물류 장비와 동일한 AX210 무선랜을 사용하지만 드라이버 버전이 24.70.0.3으로 다르다.

또한 장애 장비의 Wi-Fi 신호 세기가 정상 장비보다 반드시 약한 것은 아니므로, 단순 신호 부족보다는 드라이버 호환성, DFS 채널 동작, 802.1X 인증 등을 우선 조사할 필요가 있다.

현재는 드라이버 버전과 AP 채널이 동시에 달라 원인을 확정할 수 없으므로, 장애 시각의 Windows WLAN 이벤트 및 AP 컨트롤러 로그를 분석하고 드라이버·채널 조건을 각각 독립적으로 변경하는 검증 시험을 진행할 예정이다.
